## Repository overview

The project has an Android application module (`app`), shared Kotlin modules (`shared`, `sharedUi`), native build code (`native`), and Gradle wrapper/configuration (`gradle`). There is no `.git` directory here, so tracked-file status and a Git diff cannot be inspected. The production build produces `arm64-v8a`, `armeabi-v7a` and a universal APK. The fork is now an on-device player: YouTube Music/InnerTube streaming, the add-on sources, downloads, Cast, Listen Together, Discord, WebDAV/SMB and Wear OS are removed. The only remaining online features are lyrics, translation/romanization and Last.fm.

## `.github/`

### `workflows/android.yml`

- Runs on pushes to `main`, pull requests, tag pushes (`v*`) and manual dispatch; `contents: write` is granted for releases.
- Uses Ubuntu 24.04 and JDK 17 (Temurin), with Gradle dependency caching and a full-history checkout for generated release notes.
- Materializes `sharedUi/src/commonMain/composeResources` from `build-support/composeResources` first, as Compose resources must be regular files.
- Restores the release keystore from `RELEASE_KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS` and `RELEASE_KEY_PASSWORD` and writes `keystore.properties`. A tag/manual release fails without it; branch and PR builds fall back to the debug key.
- Builds `-PapkAbis=arm64-v8a,armeabi-v7a`, producing `app-prod-arm64-v8a-release.apk`, `app-prod-armeabi-v7a-release.apk` and `app-prod-universal-release.apk` with the same key, and passes optional `LASTFM_API_KEY`/`LASTFM_SECRET`.
- Copies the three APKs to `dist/Juni-v<version>-<abi>.apk`, uploads them as one artifact, and on a tag (or a manual tag input) publishes a GitHub Release with `softprops/action-gh-release` and generated notes.
- A manual run without a tag builds and uploads artifacts only; the same happens for every `main` push and pull request.

The wrapper directory contains only `gradle-wrapper.properties` and the binary wrapper JAR. The properties pin the Gradle 8.14.6 binary distribution; the JAR is 59,203 bytes with SHA-256 `E996D452D2645E70C01C11143CA2D3742734A28DA2BF61F25C82BDC288C9E637`. Its binary contents were not treated as line-oriented source. Root `gradlew` and `gradlew.bat` are standard Apache-2.0 Gradle launchers: the POSIX script handles symlinks, Java selection, platform path conversion and wrapper invocation; the batch script resolves the project path, selects Java and invokes the same wrapper main class. Both were read through EOF.

### Vendored backdrop renderer, `backdrops/`

### `analyzer/audio_analysis.cpp`

- This offline DSP analysis implementation is attributed to Orchard and carries an AGPLv3-or-later notice in its header. It has no direct network calls. Its public orchestration accepts decoded float PCM and sample rate, then combines RMS envelope analysis, tempo analysis, loudness/peak/dynamic range, FFT-based chroma/key and spectral estimates, energy curves, vocal-activity estimates, and transition/phrase cues.
- Envelope analysis uses nominal 250 ms RMS windows, percentile noise/reference levels, sustained activity to estimate audible start, trailing silence for content end, and separate internal-silence logic for a possible mix-out point. It also avoids treating a returning loud section as an outro by checking for quiet-then-recovery patterns.
- Spectral analysis uses sparse 4096-sample Hann-window frames and an in-file radix-2 FFT. Chroma is compared with major/minor key profiles; vocal probability is a bounded band-ratio/flatness heuristic, explicitly not a classifier. Per-frame low-band energy and vocal probabilities are sampled onto the compact energy-curve grid.
- Structure analysis assumes 4/4 and 32-beat phrases, refines intro/outro/breakdown boundaries from energy and downbeats, and emits pickup/intro-drop/main-drop and energy-cliff/outro/content-end cues. The comments warn that estimates are heuristics; the reported â€œLUFSâ€ is specifically RMS dBFS minus 0.691, not gated K-weighted loudness.
- `AnalyzeAudio` returns an empty/default result for empty samples, sample rates below 1 kHz, or non-positive duration. It calls `AnalyzeTempo` from the analyzer module, so this file is not standalone; the JNI and Kotlin callers still need tracing.
- `audio_analysis.h` defines the shared result records and documents the contract: mono contiguous float PCM, worker-thread-only O(n) analysis, caller-owned input, reentrant result-owning functions, and a separate tempo tracker whose beat positions are not evenly spaced.
- `mel_spectrogram.h` and `mel_spectrogram.cpp` compute the Beat This! model input at exactly 22,050 Hz: 1024-point periodic Hann STFT, 441-sample hop, 128 sparse Slaney mel filters from 30â€“11,000 Hz, normalized magnitude, and `log1p(1000 * energy)`. They refuse other sample rates or too-short input; the caller must resample. The model-specific constants are explicitly treated as a trained-input contract. `vocal_spectrogram.h` and `vocal_spectrogram.cpp` create open-unmix's planar stereo 44.1 kHz, 4096-point periodic-Hann raw-magnitude STFT with 1024 hop, stored directly as `[channel][bin][frame]` for ONNX; they reject wrong sample rate/channel count/short input. These two front ends intentionally duplicate private radix-2 FFT and Hann helpers to keep contracts local. The vocal front end feeds optional open-unmix masking, distinct from the simpler heuristic vocal probability in `audio_analysis.cpp`.
- `resampler.h` and `resampler.cpp` provide a mono float windowed-sinc converter with 32 zero crossings and Blackman window. Whole-number rates use precomputed exact polyphase taps (up to 1024 phases); uncommon nonintegral rates use an interpolated kernel table. They clamp edge samples and normalize realized weights to preserve DC gain; bad rates/empty input return empty and equal rates return a copy. This is worker-thread analysis support, not output resampling.
- `loop_mix_renderer.h` and `loop_mix_renderer.cpp` implement the Signalsmith-based two-deck renderer summarized under `native/loopmix/`; the header defines deck knot/loop/filter/gain state and the renderer contract, while the implementation processes ordered blocks, prerolls/stretch-seeks each deck, renders bounded input, applies gain/shelf/high-pass envelopes and the final handover fade. Callers must provide decoded planar audio and valid ordered knots before `prepare()`; this native layer does not fetch or decode media.
- `tempo_analysis.cpp` creates full-band and sub-150 Hz spectral-flux onset envelopes from 512-sample Hann windows / 128-sample hops, normalizes them, and searches 70â€“200 BPM with bounded autocorrelation. It resolves half/double-time metrical ambiguity using a tempo prior, refines lag/phase, then runs a bounded two-pass phase-locked loop across up to 20 minutes to track beats and correct drift. Bass-band evidence selects the four-beat downbeat offset. It returns zero tempo for short/silent input and rejects non-finite/out-of-range results; confidence is a heuristic combination of correlation, phase, and candidate separation. It calls no network or ML model.
